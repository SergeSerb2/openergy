# Immediate rebind failures: source and saved-evidence causal review

2026-10-23. Research only. **Neither historical bind failure has a proven specific cause. No new concrete P1/P2 product defect is established. Both runs remain FAIL.**

The invalid inference is that closing product descriptors, or observing owned processes gone, must make a new **non-reusing** socket bind succeed immediately. The strict bind predicate measures more than product descriptor release. It also depends on kernel endpoint state and the new socket's bind rules. It is a valid strict historical requirement; it is not an equivalent test of product resource ownership or of restarting the product listener. This distinction does not waive that requirement.

There is a concrete source-based candidate for A that does not require server-side TIME_WAIT: the raw accepted socket is retained after EOF and closed immediately before the non-reusing bind. A server endpoint still finishing passive close could conflict. Its state at that bind was not saved. B has stronger tuple evidence for a different candidate: a later TIME_WAIT row has **local** port 65202 and matches the rejoined connection. That row still does not record the kernel decision at bind. Neither candidate is a causal finding.
