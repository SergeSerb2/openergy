# Future external parent and consumer contract

This document is a proposed interface, not an implementation or clearance.
execution=false. All actual parent, source-association, review, design,
render, exit, EOF, D4 and runtime bindings remain null in this packet.
No staging or use follows from a source hash or a fresh guard name.

Before any target access, a future parent must bind a fresh FULL independent
review of the complete source/packet, the completed recoveryR2 design and the
exact composition. It must authenticate the fixed SYSTEM3.9.6 stdin entry,
exact argv `['-']`, full profile and original clock/transport enclosure.
There is no private interpreter or startup-environment exception.

Rendering may change only the one CONFIG_TEXT string token. The parent must
retain full original/rendered bytes, exact token span, prefix and suffix;
restore the original token byte-for-byte and recover the full template hash;
compare normalized ASTs with only that constant's value normalized; parse
strict closed CONFIG JSON; verify its canonical identity, every exact source
and full review binding, and final payload length <=1MiB. A hash written by
the payload is not proof of its own executed source association. Actual
stdin association remains an external parent observation. No renderer or
new local driver is implemented here.

The parent must inspect the full seven original completed-file provenance
records in their real locations. Only five are remote ROOT reads. The local
source-files-once.guard and source-files-parent-result.json must stay local.
It must bind exact old SOURCE v2, all53 actual statuses,50 comparisons,212
raws and six source boundaries; the old publisher, eight DATA leaves, five
build records, all supporting raw references and ABI/plist/no-transfer data;
and the fixed proof references used by the capsule. A provenance map is not
a declaration that its local entries exist remotely. Public saved references
are not freshly reopened private originals in this implementation task.

The capsule has one clock origin: its first remote CLOCK_MONOTONIC6 sample.
Remote128 and collection/publication120 derive from that sample. The parent's
local envelope remains work130 + reap2 + retention3 =135 from its own original
local start. It must establish actual causal enclosure, not compare raw local
and remote origins or assume a transport latency. Every actual capsule,
collector and transport exit, real reap, both EOFs, no loss/error/deadline,
full raw/receipt retention and D4 must be established at the correct layer.
The capsule's receipt has null fields for its own external exit/EOF/D4.
The parent must retain the actual console bytes, actual exit and full prior
leaves. A compact line alone cannot establish a successful collection.

The parent owns exclusive ROOT/no other mutators through exit. It must retain
the original once semantics, protect the burned failed local operation and
all old bytes, and reject missing/extra/partial data. It must inspect NI15
inheritance and the full profile. Entry/final NI samples do not establish a
continuous priority claim. The capsule never signals a group, searches for
processes or assumes the result of a kill syscall.

The proposed closed DATA schemas are in contracts.schema.json; CONFIG has
its own closed schema. They describe shapes and scalar domains. Semantic
relations, raw-to-Base64/hash equivalence, exact reference bytes, real OS
status, ordered clocks, no-loss causality and crash durability still need
actual parent inspection. All status exit domains are signed integer/null.
Null remains unknown; no positive PID or requested signal implies an exit.

For capture, require its exact schema, fixed ROOT and clock, nine ordered
labels/statuses/raw pairs, full actual direct-child set and actual0/reap/
bothEOF/no KILL/error/overflow/drop/deadline for every child. Validate full
Base64, decoded lengths and SHA256 before UTF8 interpretation. Require both
closed source helper facts and original object/executable filefacts. Match
before/after facts except their separate elapsed_seconds. The unchanged
helper authenticates the entire prefix, source, bundle, headers and modules.
Inspect all seven nonempty strict UTF8 stdout bodies and exact code objects.
Nonempty does not establish signature trust, notarization or artifact fitness.

For basis, first authenticate the exact old expected wrapper and old SOURCE
v2 with old vector identities. Require the fixed new schema, old bundle and
envelope, exactly50 five-key command records in old label order, unchanged43
records byte/data exact, seven corrected argv and actual capture UTF8 streams,
the exact new50 token projection and its canonical SHA256, changed indices
and labels, exact old references and the actual capture path/bytes/hash.
Projection canonicalization is sorted-key compact ASCII JSON without LF.
The source7 in capture and seven basis rows share one origin. Do not count
them as two independent collections. Capture must not refer to future basis
or to its own hash. Receipt may refer only to its three prior durable leaves;
its own postwrite/close/exit facts remain external.

A future COPYv4 consumes the exact four ACTUAL supplement pins through the
closed consumer interface. It must authenticate old SOURCE v2 using OLD50
vectors, including their historical bad seven rows as DATA ONLY. It must
verify unchanged43 rows against old expected basis and old SOURCE under the
unchanged verify-only sorted-complete-splitlines and other strict UTF8 rules.
For seven requirements rows it must use the corrected projection, new basis
and actual capture. It must compare actual COPY stdout/stderr to the new
SOURCE seven, after only the declared exact bundle-prefix substitution.
It must not compare new seven bodies with old empty strings, infer them from
`:-`, or use the bad vectors as a fallback. Entitlements and other43 vectors
stay exact. Its full success sequence remains helper-before/native50/helper-
after,52 observations with real statuses and complete raw retention. The
actual v4 caller, materializer, schemas and parent composition are absent here.

Future prepareR8 must extend the exact R7 initial260 by four actual durable
supplement pins to264. Its own four INITIAL entry outputs then make268.
It must recheck the actual four bytes/hashes and count/cap accounting, with
no second writer, ledger reset, deletion or overwrite. It must require a
CURRENT parent artifact semantic gate over old8 and the actual new7 bodies,
statuses, full retention, transport0/EOF/D4 BEFORE any private file prepare.
Neither the old artifact gate Booleans nor this capsule's DATA-only status
can supply that gate. No waiver or ordering exception is permitted.

The four runtime output caps do not guarantee that arbitrary bounded native
streams fit. Combined1MiB is per observation before JSON/Base64 expansion.
Capture256KiB, basis1MiB and receipt16KiB are separate publication ceilings.
Overflow/missing/unknown data cannot qualify. Partial publication is retained,
never overwritten or completed by a second attempt. No extra fallback leaf
or failure-pack guarantee exists. If any child is unknown/unreaped, the only
remaining actions are bounded local handle/descriptor handling, one compact
console attempt if admitted, and raw os._exit; no target publication follows.

Compact console contract: v/state/r plus c (attempted signed exits in order),
n (attempt count; later observations missing), reaped/eof/kill/loss bitmasks,
p (four publication states in fixed output order:0 not attempted,1 attempted,
2 durable,3 failed/partial), raws_unpublished and f (bounded first cause).
There is one nonblocking FIFO write <=512 with exact count, no retry or flush.
It is a lossy compact failure summary. A missing/failed line remains missing.
The external parent must not promote it to a full receipt or acceptance.

Fresh review may change this proposal. The standing repair scope needs no
new routine user confirmation. Technical review/composition and actual
evidence gates remain mandatory. This component accepts no artifact, COPY,
ordinary/runtime, native UI, whole-flow NI15, updater or release result.
